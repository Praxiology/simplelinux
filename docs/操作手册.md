# SimpleLinux 操作手册（运行与测试指南）

本手册面向 SimpleLinux 教学内核的使用者/贡献者，逐功能点说明**前置条件、运行步骤、测试脚本用例与预期效果**。覆盖 Phase 0.5–8 全部能力。所有命令均基于仓库实测；预期效果摘自真实 QEMU 串口日志。

---

## 1. 项目总览

单仓库、Rust `no_std` 内核，workspace 结构：

| 成员 | 路径 | 角色 |
|---|---|---|
| `simplelinux`（根包） | `Cargo.toml` / `src/main.rs` / `build.rs` | 宿主侧 **runner**：编译内核→用 `bootloader` 打包 BIOS 镜像→拉起 QEMU |
| `kernel` | `kernel/` | 内核本体（`x86_64-unknown-none`），所有 Phase 2–8 代码在 `kernel/src/` |
| `simplelinux-user` | `user/` | 用户态支持 crate；用户 ELF 由 `tools/*.py` 手写汇编生成 |

内核按阶段累加能力，`kernel/src/main.rs::kernel_main` 是初始化编排中枢，严格按依赖顺序接线：

```
P0.5 workspace → P2 中断/GDT/IDT/PIT → P3 PMM/VMM/heap → P4 调度
   → P5 用户态/syscall/ELF → P6 VFS → P7 键盘+e1000 → P8 网络栈+Shell
```

教学约束（贯穿）：每个 `.rs ≤ 400 行`、每个函数 `≤ 60 行`、选最朴素算法、用 Rust 类型系统表达 OS 概念、不做 SMP/COW/信号/ext2/swap。

## 2. 环境前置条件

### 2.1 必需工具
- **Rust nightly 工具链**：`rust-toolchain.toml` 锁定 `channel = "nightly"`，组件 `rust-src`、`llvm-tools`，目标 `x86_64-unknown-none`。首次 `cargo` 会自动安装（需联网）。
  ```
  rustup toolchain install nightly --component rust-src,llvm-tools
  rustup target add x86_64-unknown-none
  ```
- **QEMU**：`qemu-system-x86_64`（实测版本 10.0.13 / Debian）。
- **Python 3**：生成用户 ELF 与 initrd（`tools/*.py`），仅用标准库。

### 2.2 Cargo 配置
- `.cargo/config.toml` 开启 `bindeps`（unstable artifact-dependencies），根 runner 依赖 `kernel` 的 `x86_64-unknown-none` 产物。因此**必须用 nightly 且带 `RUSTC_BOOTSTRAP`/nightly 通道**，稳定版无法构建。
- 内核依赖（`kernel/Cargo.toml`）：`bootloader_api 0.11`、`x86_64 0.15`、`uart_16550 0.3`、`lazy_static 1.5(spin_no_std)`、`spin 0.9`、`linked_list_allocator 0.10`、`pic8259 0.11`、`pc-keyboard 0.7`。

### 2.3 ⚠️ 关键陷阱
- **必须构建 runner，不能直接构建 kernel**：
  - ✅ `cargo build -p simplelinux`（或 `make build`）
  - ❌ `cargo build -p kernel`（会按宿主 target 链接，报 `duplicate symbol _start`）
- **`panic = "abort"`**：dev/release profile 均配置，内核无栈展开。
- **no_std debug 三重故障史**：位图分配器历史上因按值迭代大数组撑爆 80KiB 栈触发 triple fault；如改动 `memory/pmm.rs` 位图逻辑，注意保持惰性/借用迭代。

## 3. 构建与运行

### 3.1 Makefile 目标（推荐入口）
```
make build     # cargo build -p simplelinux          —— 编译内核并生成 BIOS 镜像
make run       # cargo run  -p simplelinux           —— 构建并启动 QEMU（串口走 stdio）
make release   # cargo run --release -p simplelinux  —— Release 运行
make debug     # cargo run -p simplelinux -- -s -S   —— 启动 QEMU 并 gdbstub 等待连接
make initrd    # python3 tools/make_initrd.py        —— 重新生成 user/initrd.tar
make clean     # cargo clean
```

### 3.2 `make run` 实际执行的 QEMU 命令
runner（`src/main.rs`）会启动：
```
qemu-system-x86_64 \
  -drive format=raw,file=<BIOS_PATH> \
  -m 128M -serial stdio -display none -no-reboot \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04 \
  -netdev user,id=n0,hostfwd=tcp::1234-:1234,hostfwd=udp::9999-:9999 \
  -device e1000,netdev=n0
```
> `-display none`：无图形窗口，因此没有真实 PS/2 键盘输入（见 §9 已知限制）。

### 3.3 手动运行 + 抓取串口日志（用于验证脚本）
BIOS 镜像路径随包名/ profile 变化，用 `find` 定位：
```
IMG=$(find target -name "bios.img" | head -1)
timeout 25 qemu-system-x86_64 -drive format=raw,file=$IMG \
  -m 128M -serial file:/tmp/serial.log -display none -no-reboot \
  -netdev user,id=n0 -device e1000,netdev=n0
```
`timeout` 到期返回码 124 属正常（内核是常驻循环，不会自行退出）。

### 3.4 一键冒烟检查
```
make build && make initrd
IMG=$(find target -name "bios.img"|head -1)
timeout 25 qemu-system-x86_64 -drive format=raw,file=$IMG -m 128M \
  -serial file:/tmp/serial.log -display none -no-reboot \
  -netdev user,id=n0 -device e1000,netdev=n0
grep -i "panic\|triple fault\|double fault" /tmp/serial.log && echo "FOUND FAULT" || echo "OK: clean run"
```
预期最后一行输出 `OK: clean run`。

## 5. Phase 2 — 中断与定时器（GDT/IDT/PIC/PIT）

- **代码**：`kernel/src/gdt.rs`、`interrupts.rs`、`timer.rs`。
- **前置条件**：Phase 0.5。GDT/TSS 先于 IDT 加载；PIT 在调度器就绪后启动。
- **运行步骤**：`make run`，观察启动早期日志。
- **测试用例与预期效果**：
  | 用例 | 触发 | 预期日志 |
  |---|---|---|
  | GDT/TSS 加载 | 自动 | `[gdt] GDT + TSS loaded (user CS=0x23 SS=0x1b, RSP0 ready)` |
  | IDT + PIC 重映射 | 自动 | `[int] IDT loaded, PIC remapped, interrupts enabled` |
  | PIT 100Hz | 自动 | `[timer] PIT channel 0 programmed to 100 Hz (divisor=11931)` |
  | 主动断点 | `main.rs` 执行 `int3` | `[int] BREAKPOINT (int3) hit: InterruptStackFrame{...}` 后 `[main] returned from int3` |
  | 时钟计数 | 调度器运行后 | `tick=100` / `tick=200` / `tick=300`（每 ~1s） |

## 6. Phase 3 — 内存管理（PMM / VMM / heap）

- **代码**：`kernel/src/memory/{mod,pmm,vmm,heap}.rs`。位图物理帧分配器 + `OffsetPageTable` 映射 + `linked_list_allocator` 全局堆。
- **前置条件**：Phase 2（page fault 诊断）。`memory::init` 必须在任何 `Vec/Box/String` 使用前调用。
- **测试用例（`memory_self_test`）与预期效果**：
  ```
  [memory] phys mem mapped at 0x...; N usable regions, 30540 free frames
  [heap] 1024 KiB kernel heap mapped at 0x...
  [mem-test] frames free: 30281 -> 29281 -> 30281 (expected -1000 then restored)
  [mem-test] heap used=4 KiB free=1019 KiB; data[4095]=0xab v[99]=9801
  ```
  判定：分配 1000 帧后计数精确 -1000，释放后**复原**；`vec![0u8;4096]` 与 `Vec<u32>` push 成功可读写。

## 7. Phase 4 — 进程与轮转调度

- **代码**：`kernel/src/process/{mod,task,scheduler,context}.rs`。`RoundRobinScheduler`（`Vec<Option<Task>>` 稳定槽位 + `spin::Mutex`），`__switch` 汇编，`DEFAULT_SLICE=2`。
- **前置条件**：Phase 2（tick）、Phase 3（堆）。`process::init()` 先于 `timer::init()`。
- **API**：`spawn / start / yield_now / sleep / join / task_count / snapshot`。
- **测试用例（`phase4_demo`）与预期效果**：
  | 用例 | 预期日志 |
  |---|---|
  | 3 worker 交错 | `[t1] iter 1 (tick=4)`、`[t2]...`、`[t3]...` 逐轮交错，各 5 轮后 `[t1] finished` 等 |
  | join 阻塞 | `[manager] joined all workers; alive=3` |
  | 32 任务压力（两轮） | `[stress] round1 heap=.. frames=.. \| round2 heap=.. frames=.. (stable)` |
  | 收尾 | `[manager] Phase 4 demo complete` |
  判定：`(stable)` 表示堆/帧无泄漏（两轮数值稳定）。

## 8. Phase 5 — 用户态 / syscall / ELF 加载

- **代码**：`kernel/src/gdt.rs`(user 段+TSS rsp0)、`process/elf.rs`(最小 ELF64)、`syscall/mod.rs`(`int 0x80` 裸汇编入口 + dispatch)。
- **系统调用 ABI**：`int 0x80`，`rax`=号，参数 `rdi/rsi/rdx`，返回 `rax`（负值=错误码）。
  调用号：`Write=1, Exit=2, Open=3, Read=4, Close=5, Socket=6, Bind=7, Connect=8`。
- **前置条件**：Phase 3（页表/堆）、Phase 4（Task）。SMAP 在 `syscall::init()` 关闭。
- **测试脚本**：`python3 tools/gen_hello_elf.py`（默认输出 `user/hello.elf`）——手写 x86-64 汇编：`write(1,"hello from user...",..)` 后 `exit`。
- **运行步骤**：ELF 经 `include_bytes!` 内嵌进内核，`make run` 时由 `syscall::run_user(USER_ELF)` 加载执行。
- **预期效果**：
  ```
  [main] Phase 5: running hello.elf in ring3
  [syscall] entering ring3: entry=0x400000 stack=0x500000
  Hello from user ring3!
  [kernel] user program exited (code=0)
  [syscall] back in ring0 from user mode
  ```

## 9. Phase 6 — 虚拟文件系统（VFS）

- **代码**：`kernel/src/fs/{mod,vfs,devfs,procfs,initrd}.rs`。`trait FileSystem` / `trait Inode`，挂载表最长前缀匹配，路径逐级 `lookup`，全局 fd 表（≤64），fds 0/1/2 → `/dev/console`。
- **前置条件**：Phase 5（syscall 通道）。`fs::init()` 在任何用户程序运行前。
- **测试脚本**：`make initrd`（= `python3 tools/make_initrd.py`）生成 `user/initrd.tar`（ustar，含 `motd.txt`、`about.txt`、`etc/motd`）；`python3 tools/gen_vfs_elf.py` 生成 `user/vfs.elf`（`open("/dev/console")+write`）。
- **测试用例（`phase6_self_test`）与预期效果**：
  ```
  [vfs] mounted devfs at /dev ... procfs at /proc ... initrd at /initrd
  [vfs] /dev, /proc, /initrd mounted; fds 0-2 -> /dev/console
  [fs-test] ls /initrd -> ["etc", "about.txt", "motd.txt"]
  [fs-test] ls /dev -> ["console", "null", "zero", "kbd"]
  [fs-test] cat /initrd/motd.txt (38 bytes): Welcome to SimpleLinux (Phase 6 VFS)!
  [fs-test] cat /proc/meminfo (.. bytes): MemTotal.. FreeFrames..
  [fs-test] open /nope -> NotFound
  ```
  ring3 侧：`[main] Phase 6: running vfs.elf ...` → `Hello via VFS /dev/console!`。

## 10. Phase 7 — 设备驱动（键盘 + e1000）

### 10.1 键盘（IRQ1 → `/dev/kbd`）
- **代码**：`kernel/src/drivers/keyboard.rs`（`pc-keyboard` 解码 + `VecDeque` 环形缓冲）。
- **前置条件**：Phase 2（IRQ）、Phase 6（`/dev` 注册）。
- **测试用例（`phase7_demo`）与预期效果**：注入 "hello" 的 make-scancode 后经 VFS 读回：
  ```
  [kbd-test] /dev/kbd read 5 bytes: 'hello'
  ```

### 10.2 e1000 网卡
- **代码**：`kernel/src/drivers/e1000.rs`（PCI 枚举/BAR/复位/MAC/RX+TX legacy 描述符环、`send`/`poll_receive`）+ `e1000/arp.rs`（ARP demo）。
- **前置条件**：Phase 3（DMA 物理页）。QEMU 需 `-netdev user -device e1000`。
- **运行步骤**：`make run`（`phase7_setup` 初始化，`phase4_demo` 里作为任务 `demo_arp`）。
- **预期效果**：
  ```
  [main] Phase 7: initializing e1000 NIC
  [e1000] device found, BAR0 MMIO base = 0xfebc0000
  [e1000] PCI cmd=0x107 (mem=true, busmaster=true)
  [e1000] MAC 52:54:00:12:34:56, link up
  [e1000] ARP request who-has 10.0.2.2 (42 bytes)
  ```
- **⚠️ 已知限制**：在本 QEMU build 上，**TX 完成无法从 guest MMIO 观测**（诊断实验证明 MMIO 读写/`set_ics` 通路完好、guest 侧字节级全对，但 `start_xmit` 不置 `ICR.TXQE`，`pcap` 恒 0 包）。因此 ARP 应答看不到：
  ```
  [e1000] no ARP reply seen on this QEMU build (TX-completion limitation)
  [e1000] RX rdh=0 rdt=7 icr=0x0 desc_dd=[0,0,0,0,0,0,0,0]
  [e1000] TX tdh=0 tdt=7 tctl=0x1 desc0(status=0x0 cmd=0x19 len=53)
  ```
  这是 **emulator 级限制**，非驱动缺陷；网络栈验证因此改为 §11 的"注入合成入站帧驱动解码/构造"。

## 11. Phase 8 — 网络栈 + Shell

### 11.1 网络栈（`kernel/src/net/`，自底向上分层，每文件 ≤400 行）
| 文件 | 职责 |
|---|---|
| `mod.rs` | `init`/`pump`、RFC1071 `checksum`、`next_hop_mac` 路由、分层自测驱动 `demo` |
| `ethernet.rs` | 14B Ethernet II 头 + `MacAddr` newtype + EtherType 分发 |
| `arp.rs` | `BTreeMap<IPv4,MAC>` 学习缓存 + 请求/应答 |
| `ip.rs` | 固定 20B IPv4 头 + 头校验和 + 按 protocol 分发 |
| `icmp.rs` | echo request/reply（支撑 `ping`） |
| `udp.rs` | 8B 头 + IPv4 伪首部校验和 + 按端口投递到 socket |
| `tcp.rs` | 最小 `TcpState` 状态机（Listen→SynReceived 一步演示） |
| `socket.rs` | BSD socket 表 + `SocketInode impl Inode`（"网络也是文件"） |

- **前置条件**：Phase 6（VFS/socket fd）、Phase 7（e1000 收发字节管道）。`net::init()` 在 `e1000::init()` 之后。
- **集成点**：
  - `Inode::sock_index()` trait 钩子（多态定位 socket，无 downcast）+ `fs::install_inode()`。
  - 新增 syscall `Socket/Bind/Connect`；`send/recv` 复用 socket fd 的 `write/read`。
- **运行步骤**：`make run`；`phase8_setup` 会调用 `net::demo()` 逐层自测，再注入脚本化 shell 会话。
- **测试用例（`net::demo`）与预期效果**（真实日志摘录）：
  ```
  [main] Phase 8: bringing up the network stack
  [net] stack up: ip=10.0.2.15 gw=10.0.2.2
  [arp] learned 10.0.2.2 -> 52:54:00:12:34:02 ; gateway resolved (cache size 1)
  [ip] 10.0.2.2 -> 10.0.2.15 proto=1 len=39
  [icmp] echo request ... -> reply ; echo request checksum ok = true ; built reply type=0 checksum ok = true
  [udp] 10.0.2.2:7 -> :9999 (14 bytes) ; [sock] delivered 14 bytes ... socket 0 recv 14 bytes 'hello over udp'
  [tcp] 10.0.2.2:51000 -> :80 SYN seq=777 ; state Listen -> SynReceived (sent SYN-ACK on :80)
  [sock] socket 0 bound :5555 -> fd Ok(4) ; read(fd) -> 9 bytes 'ping-pong'
  ```
  判定：各层校验和 `ok = true`；socket 经 VFS fd 成功 `read` → "网络也是文件"成立。

### 11.2 交互式 Shell（`kernel/src/shell.rs`）
- **形态**：内核任务读取 `/dev/kbd`（非 ring3，因用户 ELF 为手写固定产物，交互式 read-eval 在 ring3 不现实）。
- **内置命令**：`help / echo / ls / cat / ps / free / ifconfig / arp / netstat / ping / net / exit`。
  - `ps`→`process::snapshot()`；`free`→PMM/heap；`ls`/`cat`→VFS；`ifconfig`/`arp`/`netstat`/`ping`→net 栈。
- **测试脚本**：`drivers::keyboard::inject_str("<命令>\n…\nexit\n")` 注入脚本化会话（`phase8_setup` 已内置）。真实键盘输入需去掉 `-display none`。
- **预期效果**（prompt 为 `# `）：
  ```
  SimpleLinux shell (Phase 8) — type 'help' for commands.
  # commands: help echo ls cat ps free ifconfig arp netstat ping net exit
  # e1000: ip=10.0.2.15 gw=10.0.2.2 mac=52:54:00:12:34:56
  #   10.0.2.2 -> 52:54:00:12:34:02
  #   proto local peer queue
  #     udp 0 5555 - 0
  # [icmp] ping 10.0.2.2 seq=1 (24 bytes) ... seq=3
  # heap used=.. KiB free=.. KiB | physical free frames=.. (.. MiB)
  # [pid] state  1 ready 2 blocked ...
  # /initrd: ["etc","about.txt","motd.txt"]
  # Welcome to SimpleLinux (Phase 6 VFS)!
  ```

### 11.3 关于"主机侧外部测试"的说明
计划期望的主机验证 `ping 10.0.2.15`、`echo hi | nc -u -w1 127.0.0.1 9999` 依赖**出站 TX 完成**；受 §10.2 的 QEMU 限制，这些在 host 侧不可观测。因此 Phase 8 采用**注入合成入站帧驱动 decode→构造→应答**的确定性内部验证替代，覆盖同样的分层逻辑与校验和正确性。

## 13. 已知限制与故障排查

| 现象 | 根因 | 处置 |
|---|---|---|
| `cargo build -p kernel` 报 `duplicate symbol _start` | 直接构建内核按宿主 target 链接 | 用 `-p simplelinux` |
| 出站包 host 抓不到 / ARP 无应答 | e1000 TX 完成在本 QEMU build 不可观测 | 用 §11 注入式内部验证 |
| 日志"卡在 spawning Phase 4 demo" | `timeout` 太短或 `grep` 截断误判 | 延长 timeout 到 25s、`tail` 完整日志 |
| `-display none` 下 shell 无输入 | 无图形窗口→无真实 PS/2 | 用 `keyboard::inject_str` 脚本，或去掉 `-display none` |
| 启动三重故障 | debug 大栈帧 / 位图按值迭代 | 已配 `kernel_stack_size=512*1024`；保持位图惰性迭代 |
| `bindeps` 相关报错 | 用了稳定工具链 | 切 nightly（`rust-toolchain.toml` 已锁） |
